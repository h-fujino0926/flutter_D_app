## 1. アプリの概要

### 1.1 何を作るか
PCのデスクトップ上に「付箋」のようにタスクを貼って管理できる、**チーム向けのリアルタイム共有タスク管理アプリ**。

### 1.2 解決したい課題
- チーム制作では複数人が別々のタスクを並行して進めるが、口頭や個人メモでは情報が分散し、抜け漏れや進捗の把握漏れが起きる。
- タスクを確認するたびに専用アプリを開くのが面倒で、確認頻度が下がる。

### 1.3 解決方法
- タスクを付箋としてボードに登録・配置し、担当者・期限・進捗をチーム内でリアルタイム共有する。
- 自分の担当タスクだけを**PC画面右端の常駐ミニウィンドウ（最前面表示）**に出し、別作業中でも目に入るようにする。

### 1.4 利用者と規模
- 想定ユーザー：学校のチーム開発、企業の小規模開発チーム
- 1チーム 5〜10人。1ユーザーは複数チームに所属できる。
- ロールは「チームリーダー」と「一般メンバー」の2種類。

### 1.5 2つの利用モード
| モード | 画面 | 目的 |
|---|---|---|
| **管理モード** | メインウィンドウ（ボード画面） | チーム・ボード・付箋の作成／編集／割り当て／レビュー |
| **日常モード** | 画面右端の常駐ミニウィンドウ | 所属する全チームの「自分の担当タスク」だけを期限順に表示し、その場で完了操作できる |

### 注意（Windows対応の確認）
- `firebase_messaging`（FCM）は **Windows デスクトップ非対応**。設計書のシーケンス図には FCM とありますが、**通知は「Cloud Functions が Firestore の notifications に書き込む → アプリが購読して `local_notifier` でOS通知を出す」方式**に置き換えてください。
- `cloud_functions` パッケージの Windows 対応状況を最初に確認し、非対応なら Functions を HTTPS エンドポイントにして、Firebase Auth の IDトークンを付けて `http` パッケージで呼ぶ方式にしてください。
- 設計書（シーケンス図の一部）にある「バックエンドAPI」は、上記の Cloud Functions のことを指すものとして扱ってください。

## 4. ロールと権限（仮決定・変更可）

| 操作 | リーダー | メンバー |
|---|---|---|
| 付箋の作成・編集・移動・ステータス変更 | ○ | ○ |
| 付箋の削除・復元 | ○ | 自分が作成した付箋のみ |
| 担当者の割り当て | ○ | ○ |
| 完了タスクの承認・差し戻し | ○ | × |
| ボード作成 | ○ | × |
| 招待の発行・無効化 | ○ | × |
| メンバーのロール変更 | ○ | × |
| チーム情報の編集・削除 | 作成者（owner）のみ | × |
| チーム退出 | ○（最後のリーダー以外） | ○ |

権限チェックは **UI での非表示** と **Firestore セキュリティルール** の両方で行うこと（UIだけで済ませない）。

## 5. データ設計（Firestore）

設計書のテーブル定義（RDB形式：user / team / member / team_invite / task / task_member / notifications / user_setting / board / board_column）を Firestore に読み替えたものが以下です。ID は Firestore の自動IDを使い、`int` の自動採番は使いません。

```
users/{uid}
  displayName: string        // 必須
  email: string              // 必須
  iconColor: string          // 例 "#F4A261"
  lastLoginAt: timestamp?
  createdAt, updatedAt: timestamp
  deletedAt: timestamp?

userSettings/{uid}
  lastTeamId: string?        // 前回チーム（機能18）
  lastBoardId: string?       // 前回ボード（機能18）
  keepLoggedIn: bool         // 機能16（ローカルにも保存）
  miniWindow: { enabled: bool, alwaysOnTop: bool }
  googleCalendarLinked: bool

teams/{teamId}
  name: string, description: string?
  ownerUserId: string
  createdAt, updatedAt: timestamp, deletedAt: timestamp?

teams/{teamId}/members/{uid}
  role: "leader" | "member"   // 初期値 member（作成者は leader）
  displayName: string          // 表示用キャッシュ
  iconColor: string
  joinedAt: timestamp
  leftAt: timestamp?           // 退出時に設定（論理退出）

teams/{teamId}/boards/{boardId}
  name: string
  createdBy: string
  createdAt: timestamp

teams/{teamId}/tasks/{taskId}
  boardId: string
  title: string                 // 必須
  description: string?
  startDate: timestamp?         // 開始日
  dueDate: timestamp?           // 締切日（設計書の fixed_date）
  priority: "high" | "medium" | "low"   // 初期値 medium
  status: "todo" | "in_progress" | "done"   // 初期値 todo
  assigneeIds: string[]         // task_member テーブルの代わり
  createdBy: string
  posX: number, posY: number    // ボード上の座標（列内の相対位置）
  color: string, size: "S"|"M"|"L"
  latestComment: { text, userId, updatedAt }?   // 一言メッセージ（1件・上書き）
  completedAt: timestamp?
  completedBy: string?
  reviewedAt: timestamp?        // リーダー承認日時
  deletedAt: timestamp?         // ゴミ箱
  createdAt, updatedAt: timestamp

teams/{teamId}/tasks/{taskId}/history/{historyId}   // TaskStatusHistory
  fromStatus, toStatus: string
  userId: string
  comment: string?              // 差し戻し時のメッセージ
  createdAt: timestamp

invites/{inviteId}              // クライアントから直接読み書き禁止（Functionsのみ）
  teamId: string
  token: string                 // URL用ランダム文字列（unique）
  passcodeHash: string          // 6桁パスコードのハッシュ（平文保存しない）
  createdBy: string
  expiresAt: timestamp          // 発行 + 72時間
  maxUses: number               // 0 = 無制限
  usedCount: number             // 初期値 0
  failedAttempts: number        // 初期値 0。5回失敗でその招待を無効化
  revokedAt: timestamp?
  createdAt: timestamp

notifications/{notificationId}
  recipientUserId: string
  actorUserId: string?
  teamId: string?, taskId: string?
  type: "task_completed" | "task_returned" | "task_approved" | "message_updated" | "task_assigned"
  message: string               // 最大255文字
  read: bool                    // 既読フラグ
  createdAt: timestamp
```

### インデックス
- ミニウィンドウ用：`tasks` の collectionGroup クエリ（`assigneeIds array-contains uid` ＋ `status != done` ＋ `deletedAt == null` ＋ `dueDate` 昇順）の複合インデックスを `firestore.indexes.json` に定義。

### セキュリティルール（`firestore.rules`）
- 未ログインは全拒否（非機能要件13）。
- `teams/{teamId}/**` は、そのチームの `members/{uid}` が存在し `leftAt == null` のユーザーだけ読み書き可。
- リーダー限定操作（ボード作成、ロール変更など）はルールでも `role == "leader"` を確認。
- `invites` はクライアントから読み書き不可。
- `notifications` は `recipientUserId == request.auth.uid` のみ読み取り・既読更新可。作成は Functions のみ。
- ルールのユニットテストを `@firebase/rules-unit-testing` で書くこと。

### 6.2 P1-01 メイン（ボード）画面のレイアウト
```
┌──────────────────────────────────────────────┐
│ ⚙設定   📅カレンダー切替   [チーム▼][ボード▼]   🔍  🔔(未読数)  👤 │ ← ヘッダー
├───────────────────────────────┬──────────────┤
│  未着手        │  進行中        │  完了          │ [＋追加] [完了ログ] │
│ ┌────┐       │ ┌────┐       │ ┌────┐       │──────────────│
│ │付箋│       │ │付箋│       │ │付箋│       │ 現在のチームの   │
│ └────┘       │ └────┘       │ └────┘       │ マイタスク      │
│   ＋付箋を追加 │  ＋付箋を追加  │  ＋付箋を追加  │ （期限が近い順） │
└───────────────────────────────┴──────────────┘
```
- ボード領域は「未着手／進行中／完了」の3列（設計書の board_column）。**列の中では付箋を自由な位置に置ける**（posX/posY を保存）。
- 付箋を別の列へドラッグすると、ステータスもその列のものに変わる（完了列へ落とした場合は完了アニメーションと通知も発生）。
- 付箋カードの表示内容：タイトル、締切日、担当者アイコン、作成者アイコン（小）、優先度バッジ、一言メッセージがあれば吹き出しアイコン。
- 右パネル：現在のチームの自分の担当タスクを締切が近い順にリスト表示。
- 「完了ログ」ボタン → P1-07 へ。

### 6.3 付箋の見た目ルール
| 状態 | 見た目 |
|---|---|
| 通常 | 選択した色の付箋。ほんの少しランダムな傾き（±2°）と影で付箋らしさを出す |
| 締切まで24時間以内 | 枠をオレンジ、角に「まもなく」ラベル、軽く揺れるアニメーション（1回だけ） |
| 締切超過 | 背景を赤系、端がめくれたような形状、「期限切れ」ラベル |
| 差し戻し中 | 「差し戻し」ラベルと一言メッセージを強調表示 |
| ドラッグ中 | 少し拡大＋影を濃く |

### 6.4 常駐ミニウィンドウ（日常モード）
- サイズ：幅 280px 程度、高さは画面の高さに合わせる。画面右端に寄せて**常に最前面**。
- 枠なしウィンドウ、半透明背景。折りたたみ（細いタブだけ残す）ボタンあり。
- 表示内容：全所属チームの「自分が担当」かつ「未完了・未削除」の付箋を締切が近い順に。チーム名を小さく表示。
- 操作：
  - 付箋を右へフリック、またはチェックで完了 → めくれて飛ぶアニメーション → 5秒間 Undo 表示
  - クリックでメインウィンドウを前面に出し、該当付箋の詳細を開く
- メインウィンドウを閉じてもミニウィンドウは残る（タスクトレイ常駐。`tray_manager` などを使用）。
- 設定でON/OFF可能。

## 7. 主要な処理フロー

### 7.1 起動・ログイン
1. 起動 → ローカルの `keepLoggedIn` を確認。
2. 保持ON かつ Firebase Auth にユーザーが残っていれば自動ログイン。保持OFFならサインアウトしてP0-01へ。
3. ログイン成功 → `users.lastLoginAt` 更新 → `userSettings` の `lastTeamId` / `lastBoardId` を読み、そのボードを開く。
4. 前回チームがない（初回など）→ チーム作成 or 招待参加を促す画面へ。
5. 初回ログイン時のみ P0-05（ログイン保持設定）を表示（「次回から表示しない」で以後スキップ）。

### 7.2 付箋の作成
1. 「＋追加」→ P1-04 で入力 → 保存。
2. Firestore に `status: todo`、作成した列の空いている位置に `posX/posY` を入れて保存。
3. snapshots で全員の画面に即表示。担当者がいれば `task_assigned` 通知。

### 7.3 付箋の移動とリアルタイム同期（非機能要件：1秒未満・カクつかない）
1. ドラッグ中は**ローカルの状態だけ**を更新して即座に描画（楽観的更新）。
2. ドラッグ中の Firestore への書き込みは **200ms に1回まで**に間引く（throttle）。ドロップ時に最終座標を必ず書き込む。
3. 他メンバー側は snapshot を受け取ったら、付箋を新しい位置へ**アニメーションで滑らかに**移動。
4. 自分がドラッグ中の付箋には、他人からの位置更新を適用しない。
5. 競合は「最後に書き込んだ人が勝つ」でよい。

### 7.4 タスク完了と通知
1. 完了操作 → 0.3〜0.5秒のめくれアニメーション → `status: done, completedAt, completedBy` を更新し history に記録。
2. 画面下部に「元に戻す」トーストを5秒表示。押されたら元のステータスに戻し、`completedAt` をクリア（このとき通知は取り消さなくてよいが、可能なら Functions 側で5秒遅延してから通知する方式を検討）。
3. Cloud Functions の `onTaskUpdated`（Firestoreトリガー）が `status` の done への変化を検知 → リーダー全員とタスク作成者へ `notifications` を作成。
4. 受信側アプリは自分宛ての `notifications` を購読し、新着を `local_notifier` でOS通知＋ベルの未読数を更新。

### 7.5 レビュー（承認・差し戻し）
1. リーダーが完了タスクの詳細を開く →「承認」または「差し戻し」。
2. 承認：`reviewedAt` を設定 → 担当者へ `task_approved` 通知。
3. 差し戻し：一言メッセージ入力必須 → `latestComment` を上書き、`status: in_progress`、`completedAt` をクリア、history にコメント付きで記録 → 担当者へ `task_returned` 通知。

### 7.6 一言メッセージの上書き
1. 付箋詳細のメッセージ枠を書き換えて「更新」。
2. `latestComment` を上書き → 全員の画面の付箋に即反映。
3. Functions が担当者（と作成者、本人除く）へ `message_updated` 通知。

### 7.7 招待の発行と参加
**発行（リーダー）**
1. P1-08 で「招待を発行」→ Callable/HTTPS Function `createInvite(teamId)`。
2. Functions：リーダー権限を確認 → 有効な招待の中で重複しない6桁英数字（大文字A-Z＋0-9。紛らわしい `0/O/1/I` は除外してよい）を生成 → ハッシュ化して `invites` に保存、`expiresAt = 現在 + 72時間`。
3. 画面に「招待URL」「パスコード」「有効期限」を表示し、それぞれコピーボタン。**パスコードの平文はこの1回しか表示しない**旨を表示。

**参加（招待されたユーザー）**
1. 招待URL（例：`fusenapp://join?token=xxxx`）を開く、またはアプリの「招待で参加」にURLを貼り付ける。
2. 未ログインならログイン／新規登録を先に行い、終わったら参加フローに戻る。
3. P0-03 で6桁を入力 →「参加」→ Function `joinTeam(token, passcode)`。
4. Functions の判定順：
   - token が存在しない／`revokedAt` あり → エラー「この招待は無効です」
   - `expiresAt` を過ぎている → エラー「招待コードの有効期限（3日間）が切れています」
   - `maxUses > 0` かつ `usedCount >= maxUses` → エラー「この招待は使用上限に達しています」
   - パスコード不一致 → `failedAttempts + 1`、エラー「パスコードが正しくありません」。5回で `revokedAt` を設定
   - すでにメンバー → そのチームを開くだけ
   - 成功 → `members/{uid}` を追加（`role: member`）、`usedCount + 1` → 対象チームのボードへ自動遷移
5. Windows でのカスタムURLスキーム登録（レジストリ）は `app_links` のドキュメントに従い設定。うまくいかない場合でも「URL貼り付け」で必ず参加できるようにする。

### 7.8 ゴミ箱と復元
- 削除：`deletedAt` を設定（物理削除しない）。ボードから消え、P1-07 のゴミ箱タブへ。
- 復元：`deletedAt` を null に戻す。元の座標が埋まっていれば少しずらして配置。
- 完了ログ：`status == done` の付箋一覧。復元すると `status: todo` に戻る。
- （任意）30日経過したゴミ箱データを Functions のスケジュール実行で物理削除。

## 8. 非機能要件

| No | 項目 | 基準 | 実装上の対応 |
|---|---|---|---|
| 1 | 画面の同期 | 付箋の追加・移動などが他メンバーへ1秒未満で反映 | Firestore snapshots、楽観的更新 |
| 2 | 画面の動き | D&D中にフレームレートが落ちない（開発用ノートPCで60fps目安） | 付箋ごとに `RepaintBoundary`、ドラッグ中は該当付箋だけ再描画、書き込みは throttle |
| 3 | 同時接続 | 1ボードを5人で同時操作しても重くならない | ボード単位でクエリを絞る、不要な listen を解除 |
| 4 | セキュリティ | ログインしたユーザーのみ利用可 | Firebase Auth＋セキュリティルール |
| 5 | セキュリティ | 招待コードを持つユーザーのみ参加可 | 招待検証は Functions で行い、クライアントに passcodeHash を渡さない |
| 6 | データの永続化 | 付箋の変更は即DB保存し、再読み込みしてもリセットされない | 変更ごとに即書き込み。Firestore オフライン永続化を有効化 |
| 7 | 利便性 | 前回のチーム・ボードを記憶し再ログイン時の手間を減らす | `userSettings.lastTeamId/lastBoardId` |
| — | パスワード | 平文保存しない | Firebase Auth に任せる（自前でパスワードを保存しない） |
| — | エラー処理 | 通信エラー時もアプリが落ちない | 全 Firestore/Functions 呼び出しを try-catch、SnackBar でユーザーに表示 |

## 11. 設計書の矛盾と、このプロンプトでの決定内容

実装中に設計書を参照して食い違いに気づいた場合の判断基準です。

| 食い違い | 決定 |
|---|---|
| テーブル設計は RDB（int自動採番・enum）、シーケンス図は Firestore | **Firestore を採用**。テーブルは §5 のコレクションに読み替え |
| 通知は FCM（シーケンス図） | Windows 非対応のため、notifications コレクション＋ローカル通知に置換 |
| 招待は「チーム単位」（テーブル）と「ボード単位」（シーケンス図）が混在 | **チーム単位**で招待。参加後はチーム内の全ボードを閲覧可 |
| task テーブルに board_id・座標・開始日・色・一言メッセージがない | ドメインモデル図・機能要件に合わせて §5 のとおり追加 |
| ステータスが `done` と `completed` で混在 | `todo / in_progress / done` に統一 |
| 優先度が「高・中・低」と画面モックの「P1」で混在 | `high / medium / low`（表示は 高・中・低）に統一 |
| 画面ID P0-04 が「パスコード再発行」だが中身はメール送信完了 | パスワード再設定メールの送信完了画面として実装 |
| task_member テーブル（多対多） | `assigneeIds` 配列で表現 |
| ボード画面の「完」ボタンの意味が不明 | 完了ログ（P1-07）を開くボタンと解釈 |

この表以外で矛盾を見つけたら、実装を止めて私に確認してください。
